# Plano — Fase 3 do Blueprint: Juiz de Direção de Arte (`layoutIntegrity`)

## Objetivo
Adicionar a dimensão `layoutIntegrity` ao juiz de qualidade, alimentada pelo `validateVisualFit` + sumário geométrico. Candidatos com layout quebrado são rejeitados e revisados. Resolve o defeito estrutural **G2** ("motor criativo/QA roda antes da composição; o juiz não vê geometria").

## Escopo (confirmado com usuário)
- **Juiz visual + layoutIntegrity** (não a revisão por slot G7/G8 nesta entrega).
- **Rejeitar + revisar** candidatos com layoutIntegrity baixo.
- Juiz v1 = fit determinístico + sumário geométrico (sem screenshot headless — v2 futura).

---

## O problema estrutural (G2)

`evaluateAndReviseCandidates` (routers.ts:1477) roda **antes** de `composeVariation` (1623) e `createPostVisualSnapshot` (1627). No momento da avaliação, `EvaluatedCandidate` só carrega texto+cor (herda de `VariationDiversityInput` que **não tem** `layoutSettings`/`textElements`/`template`/`sections`/`aspectRatio`). O juiz é cego para geometria.

## Decisão arquitetural: como alimentar `layoutIntegrity`

Há duas opções. **Escolho a Opção B** (construir snapshot transitório dentro do avaliador) porque é contida, não reordena o pipeline, e reutiliza código existente.

**Opção A (reordenar pipeline):** mover `evaluateAndReviseCandidates` para depois de `composeVariation`+snapshot. — **Descartada**: muda a semântica do juiz (hoje avalia copy puro; revisão cirúrgica de texto precisa rodar antes da composição injetar geometria), alto risco, toca muito código.

**Opção B (snapshot transitório no avaliador):** estender `EvaluatedCandidate` com campos visuais (`template`, `sections`, `aspectRatio`, `layoutSettings`, `textElements`), e dentro de `computeLayoutIntegrity` construir um snapshot transitório via `createPostVisualSnapshot` + rodar `validateVisualFit`. — **Escolhida**: contida no `postEvaluation.ts`, não reordena nada, reutiliza funções puras de `shared/`.

### Etapa 3 — Implementar `computeLayoutIntegrity`
**Arquivo:** `server/ai/postEvaluation.ts` (nova função, modelo: `computeCaptionCoherence` em :164-227)

```ts
function computeLayoutIntegrity(candidate: EvaluatedCandidate): number {
  // Constrói snapshot transitório a partir do candidato
  const snapshot = createPostVisualSnapshot(
    candidate as PostVariation,
    candidate.aspectRatio ?? "1:1",
  );
  const result = validateVisualFit(snapshot);

  if (result.ok) return 100;  // sem issues = integridade máxima

  // Penaliza por tipo e severidade de issue
  const PENALTY: Record<VisualFitIssueType, number> = {
    headline_body_overlap: 35,           // grave — texto sobre texto
    structured_absolute_layout: 25,      // médio — template estruturado mal posicionado
    card_too_narrow: 20,                 // médio — card corta conteúdo
    text_element_outside_canvas: 15,     // decoração fora
    text_element_overlaps_copy: 15,      // decoração sobre texto
  };
  const totalPenalty = result.issues.reduce(
    (sum, issue) => sum + (PENALTY[issue.type] ?? 10),
    0,
  );
  return clampScore(100 - totalPenalty);
}
```

Nota: `createPostVisualSnapshot` aplica `applyVisualFitFallback` internamente, então `validateVisualFit` só vê issues **não-corrigíveis**. Isso é correto: se o fallback resolveu, integridade é alta; se sobraram issues, penaliza.

Imports necessários: `createPostVisualSnapshot` de `@shared/variationSnapshot`, `validateVisualFit` + tipos de `@shared/visualFit`, tipos `PostVariation`/`AspectRatio`/`AdvancedLayoutSettings`/`TextElement` de `@shared/postspark`.

## Riscos e mitigação

| Risco | Mitigação |
|-------|-----------|
| `createPostVisualSnapshot` no avaliador adiciona custo de compute | É matemática pura (já roda no shadow/pipeline graph); custo negligenciável por candidato |
| Rebalanceamento muda `overallScore` de candidatos existentes | Pesos preservam importância relativa; teste #5 garante score perfeito ≈ 100 |
| Revisão LLM não sabe corrigir geometria (é texto) | O feedback instrui "reduzir comprimento do body" — o revisor ajusta o texto que causa overflow; o `applyVisualFitFallback` resolve a geometria |
| LLM judge offline (`aiLlmJudgeEnabled=false`) | `layoutIntegrity` é determinístico (não depende do LLM); funciona mesmo com juiz desligado |
| `EvaluatedCandidate` estendido pode quebrar mocks de teste | Campos são opcionais; testes existentes não precisam mudar |
