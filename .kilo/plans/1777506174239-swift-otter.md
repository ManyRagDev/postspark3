# Plan: Integrar ManyLabs app_access no PostSpark

## Contexto

O Supabase já tem o schema `manylabs` com `profiles`, `app_access` e `app_roles`. A RLS já foi aplicada nas tabelas `postspark`. Agora o app precisa respeitar `manylabs.app_access` em dois pontos críticos:

1. **Login/session creation** — não emitir cookie para usuário sem acesso.
2. **Request authentication** — bloquear cookie antigo se acesso for revogado.

## Estratégia escolhida: Auto-activate (MVP)

Login/cadastro feito pelo PostSpark automaticamente cria:
- `manylabs.profiles` (se não existir)
- `manylabs.app_access` com `app_slug = 'postspark'`, `status = 'active'` (se não existir)
- `manylabs.app_roles` com `role = 'user'` (se não existir)

Cookie é emitido normalmente após ativação.

## Tarefas

### 1. Criar helper `server/_core/manylabs.ts`

Novo arquivo com funções reutilizáveis:

```typescript
// Usar Supabase service role client (sem schema fixo, default "public")
// Chamar via .rpc() ou .from() com schema explícito

async function ensurePostSparkAccess(supabaseAdmin, userId: string): Promise<void>
  - Upsert em manylabs.profiles (id = userId)
  - Upsert em manylabs.app_access (user_id, app_slug='postspark', status='active')
  - Upsert em manylabs.app_roles (user_id, app_slug='postspark', role='user')

async function hasPostSparkAccess(supabaseAdmin, userId: string): Promise<boolean>
  - Select em manylabs.app_access WHERE user_id AND app_slug='postspark' AND status='active'
  - Retorna boolean
```

Para acessar o schema `manylabs`, usar `.schema('manylabs')` no Supabase client ou `.rpc()` com path qualificado. O client Supabase JS suporta `.schema()`.

### 2. Modificar `server/_core/supabaseAuth.ts`

**Endpoint `POST /api/auth/supabase-session`** (linha ~30-53):

Depois de validar `access_token` com `supabase.auth.getUser(access_token)` e antes de emitir cookie:

1. Chamar `hasPostSparkAccess(supabase, user.id)`
2. Se `false`:
   - Chamar `ensurePostSparkAccess(supabase, user.id)` para auto-ativar
   - Se auto-ativação falhar, responder HTTP 403 com `{ "error": "postspark_access_required" }`
3. Se `true` (ou após auto-ativação bem-sucedida):
   - Emitir cookie normalmente
   - Retornar resposta de sucesso

### 3. Modificar `server/_core/sdk.ts`

**Método `authenticateRequest(req)`** (linha ~48-88):

Depois de validar o token com `supabase.auth.getUser(accessToken)` (linha ~56-64):

1. Chamar `hasPostSparkAccess(supabase, user.id)` usando o mesmo client
2. Se `false`, lançar `ForbiddenError("PostSpark access required")`

OBS: O `ForbiddenError` de `shared/_core/errors.ts` retorna HTTP 403. O tRPC middleware vai propagar como erro `FORBIDDEN`. O frontend já trata erros 403 em `useAuth` (o `auth.me` vai falhar, `isAuthenticated` será `false`).

### 4. Modificar `client/src/App.tsx` — `GoogleAuthCallback`

No componente `GoogleAuthCallback` (linha ~48-78):

O `.then()` do fetch para `/api/auth/supabase-session` deve verificar se `response.ok`. Se não for:
- Se o status for 403 e o erro for `postspark_access_required`, redirecionar para `/?auth_error=postspark_access_required`
- Caso contrário, redirecionar para `/?auth_error=session_failed`

### 5. Modificar `client/src/components/LoginModal.tsx`

Na função `exchangeSupabaseSession` local (linha ~14-25):

- Verificar `response.status === 403`
- Se o JSON retornado tiver `error === "postspark_access_required"`, mostrar mensagem: "Sua Conta ManyLabs ainda não tem o PostSpark ativado."
- Tratar como erro no `handleEmailAuth`

### 6. Modificar `client/src/_core/hooks/useAuth.ts`

No `syncCurrentSession` (linha ~29-44):

- Capturar o erro do `exchangeSupabaseSession` e verificar se é `postspark_access_required`
- Se for, logar warning mas não tratar como erro fatal (o usuário pode tentar novamente)

No `onAuthStateChange` handler (linha ~50-68):

- Mesmo tratamento para o catch do `exchangeSupabaseSession`

### 7. Atualizar `DOCUMENTO_MESTRE.md`

Adicionar seção sobre ManyLabs app_access:
- Schema `manylabs` como gate de acesso por app
- Helper `hasPostSparkAccess` e `ensurePostSparkAccess`
- Auto-ativação no login
- Verificação em `authenticateRequest`
- Fluxo de erro `postspark_access_required`
